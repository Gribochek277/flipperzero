serial: handle write-side link death (found during ticket #5 live test)
Write errors (EIO on unplug/re-enumeration) were not handled: the session
kept a dead fd and every subsequent command failed with the same EIO.
Now all tty writes go through ttyWrite() with the same fatal-error handling
as reads (dispose -> the next command reopens the port), and the error
message says which operation (read/write) failed.

Found live: after the device re-enumerated (ttyACM0 -> ttyACM1), the long-
lived extension session kept writing to the stale fd.
